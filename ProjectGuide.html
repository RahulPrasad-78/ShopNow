🛍️ ShopNow — how it all works

ShopNow is an online store. Customers browse products, put them in a cart and pay online. Admins add products and manage orders. This page explains every moving part and how the parts talk to each other, with no prior knowledge assumed.

1. The big picture

Think of a restaurant. The frontend is the dining room and menu (what the customer sees). The backend is the kitchen (where the real work and rules live). The database is the pantry (where everything is stored). Outside suppliers (payments, images, email) are delivery partners.

Who talks to whom
👤 You (browser)Chrome, Edge, phone…
shows pages
Frontend — ReactPages, buttons, cart, forms
runs inside your browser
sends requests like “GET /api/products” (HTTP + JSON)
Backend — Express (Node.js)Checks who you are, applies the rules,
talks to the database and partners
reads & writes data / calls partners
🍃 MongoDBUsers, products, orders
☁️ CloudinaryStores product photos
💳 RazorpayTakes the payment
✉️ Gmail (SMTP)Sends OTP & order emails
Golden rule: the browser is never trusted. Anything important (prices, who is admin, whether a payment is real) is decided by the backend. The frontend just asks and displays.

The journey of one request

Every time you click something that needs data, this happens:

  1. You click (e.g. open the Shop page). React runs fetch("/api/products").
  2. The request travels to the Express server.
  3. It passes through safety checks (security headers, rate limit, input cleaning, login check if needed).
  4. A route sends it to the correct controller function.
  5. The controller asks MongoDB (through a Mongoose model) for data.
  6. The server replies with JSON; React stores it in state and draws the page.

2. Technologies used

Each tool has one job.

React 19

Builds the user interface out of reusable components (Navbar, ProductCard…).

React Router 7

Switches pages without reloading (/shop, /cart, /admin…).

Redux Toolkit

Holds the shopping cart so every page can read it. Saved in localStorage.

Context API

Shares the logged-in user (AuthContext) and pop-up messages (NotificationContext).

Node.js + Express 5

The web server. Receives requests and returns answers.

MongoDB + Mongoose

Database, plus a friendly way to define what data looks like.

JWT + bcrypt

JWT = a signed “ID badge” for logged-in users. bcrypt scrambles passwords so they can't be read.

Multer + Cloudinary

Multer receives an uploaded photo; Cloudinary stores it online.

Razorpay

Payment gateway: handles cards/UPI so we never touch card numbers.

Nodemailer

Sends emails through Gmail (OTP codes, order confirmations).

express-validator

Checks incoming data is sane (valid email, price ≥ 0…).

helmet · cors · rate-limit

Security headers, allowed websites list, and anti-spam request limits.

Route guards: how a page is protected

Wrapper components (ProtectedRoute, AdminRoute) check the user before showing a page. The real protection is on the backend; this just gives a nicer experience.

Where the app remembers things (state)

AuthContext

Who is logged in (name, role, token). Saved as userInfo in localStorage so a refresh keeps you logged in.

Redux cart

addToCart, removeFromCart, clearCart. Saved as cartItems in localStorage.

NotificationContext

toast.success/error/warning/info slide-in messages and confirm() pop-up (used for “Delete this product?”).

Component state

Short-lived stuff like what you typed in a form or whether a page is loading (useState).

How does React reach the API? Code just writes fetch("/api/products"). In development the React dev server forwards /api/* to localhost:5000 (the "proxy" setting). In production Express serves the built site itself, so same address.

7. Step-by-step flows

Each journey drawn two ways: a sequence diagram (who sends what to whom, top to bottom) and a flowchart (the decisions along the way).

7.1 Creating an account (with email OTP)

OTP = One-Time Password: a 6-digit code emailed to you to prove the address is really yours.

Sequence: register as a normal user
Flowchart: the Register page

Register

Account saved with verified: false, code emailed, no login yet. Registering again with the same unverified email just updates that same record and sends a fresh code (no duplicates).

Register as Test User

No email, no OTP. Saved with verified: true and isTestUser: true, logged in instantly. Great for demos.

OTP rules

Valid 10 minutes · max 5 wrong tries · resend allowed every 60 seconds · stored only as a hash.

7.2 Logging in

Sequence
Flowchart
What is a JWT? After a successful login the server gives the browser a long, signed text string (the token). The browser attaches it to later requests as Authorization: Bearer …. The server checks the signature to know who you are, without asking for your password again. It expires after 3 days.

7.3 Browsing products

Sequence: opening the Shop page

The API returns { products, page, pages, total }. Shop asks for up to 100 at once; search on the Shop page filters those in the browser.

7.4 The shopping cart

The cart lives entirely in the browser (Redux + localStorage). The server is only involved at checkout, and it ignores the prices the browser sends.

7.5 Checkout and payment

Sequence
Flowchart: what the server checks when you press “Pay”
Why two steps? Step 1 creates the order and asks Razorpay for a payment slot. Step 2 happens only after Razorpay confirms payment and sends a cryptographic signature. The server recomputes that signature itself; if it doesn't match, the order is marked Failed and no stock changes.

7.6 Admin: adding a product with an image

Sequence

The photo is only stored on the server for a split second (backend/uploads), then uploaded to Cloudinary and deleted. That's why the folder looks empty.

10. Run it yourself

  1. Install Node.js 18+. Have a MongoDB Atlas database, and (for full features) Cloudinary, Razorpay and a Gmail App Password.
  2. In the project root run npm run install-all.
  3. Copy backend/.env.example to backend/.env and fill in the values (table below).
  4. Optional: npm run seed for sample users and products.
  5. Run npm run dev. Open http://localhost:3000.
.env variableUsed for
MONGO_URIDatabase connection
JWT_SECRET, JWT_EXPIRES_INSigning login tokens (default 3 days)
EMAIL_USER, EMAIL_PASSGmail address + App Password for OTP/order emails
CLOUDINARY_CLOUD_NAME / API_KEY / API_SECRETProduct image hosting
RAZORPAY_KEY_ID / KEY_SECRETPayments
FRONTEND_URL, PORT, NODE_ENVCORS origin, server port, mode
Never share or commit .env. It holds your secrets. .gitignore already excludes it.

11. Glossary for beginners

WordPlain meaning
APIA menu of addresses the frontend can call to ask the backend for things.
Endpoint / routeOne address on that menu, e.g. /api/products.
HTTP methodsGET = read, POST = create, PUT = update, DELETE = remove.
JSONThe text format the frontend and backend use to exchange data.
MiddlewareA checkpoint a request passes through before reaching the real code.
ControllerThe function that does the actual work for a route.
Model / schemaThe blueprint describing what a User, Product or Order looks like.
JWT (token)A signed ID badge proving you're logged in.
HashA one-way scramble. You can check a password against it but never read it back.
OTPOne-time code emailed to confirm your address.
ComponentA reusable piece of UI in React (a button, a card, a whole page).
StateData a component remembers while you use the app.
ReduxA shared box of state any component can read, used here for the cart.
localStorageA small storage area in your browser that survives refreshes.
CORSBrowser rule about which websites may call which servers.
Rate limitA cap on how many requests one visitor can make in a time window.
Signature (HMAC)A tamper-proof stamp Razorpay adds to prove a payment is genuine.
SeedFilling an empty database with starter data.
